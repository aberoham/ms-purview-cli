# Changelog

## Unreleased

- Add `purview estimate <case> <search>` (`--allow-generic --reason`, `--allow-concurrent`, `--no-wait`, `--no-download`, `--strict`, `--wait-timeout`, `--poll-interval`, `--out`). Before its plan it checks that the search covers every tenant mailbox and nothing else (`ScopeUnverified`, `ScopeNotAllowed`, `SearchHasSources`), puts the search's current query through the guard, and refuses with `ConcurrentOperation` when an estimate of the case not yet finished may be a duplicate, unless `--allow-concurrent` is given. After the one POST it reads the operation from the `Location` header (`UnexpectedLocation` otherwise), waits for it, downloads its report zip and reports `collection: complete | incomplete | unchecked` with the counts, the locations with most hits and the failed locations; `--strict` exits 4 when a location failed or the zip could not be checked.
- `estimate` warns loudly, on stderr and as `volume` in its result, when the estimate has more than `volume.warn_hits` items (default 5,000), a location with more than `volume.warn_hits_per_location` hits (default 1,000), or an indexed size above `volume.max_export_size` (default 10 GiB), all set in `config.json`. The exit code is unchanged.
- Add `purview report <case> <search>` (`--name`, `--no-teams-context`, `--allow-generic`, `--allow-large`, `--reason`, `--allow-concurrent`, `--no-wait`, `--no-download`, `--strict`, `--wait-timeout`, `--poll-interval`, `--out`). It runs the action preflight of `estimate`, refuses with `ConcurrentOperation` when an item report or export of the case not yet finished may be a duplicate, and compares the search's latest estimate with `volume.max_export_size`: above it the report is refused with `TooLarge`, and with no current estimate to compare with `VolumeUnchecked`, unless `--allow-large` is given with `--reason`, which goes into the report's description. It posts `exportReport` with Teams context on (`defaults.teams_context` or `--no-teams-context` turn it off, experimental), waits, downloads the zip and reports `collection` from its Locations file.
- Add `purview export create <case> <search>`, with the flags of `report`. It runs the same preflight, size limit, recheck and reconciliation, posts `exportResult` with `exportFormat: msg` and `additionalOptions: teamsAndYammerConversations,includeReport` (`includeReport` alone under `--no-teams-context`, experimental), waits, downloads every part into the data directory, and reports `collection` from the `Reports-…zip` part alone. The plan warns that an export holds more than the estimate counts and that the download is large.
- A stopped `estimate` (`--no-wait`, the wait deadline, Ctrl-C) now resumes with `operation get <case> <op> --wait --check`, as `report` does, instead of `operation get --wait` then `download`.
- Add `purview operation get --check`, which downloads an estimate's, item report's or export's evidence file into the data directory and reports `collection`; a later `download` reuses the file.
- Add `purview parse locations` (`--top`, `--with-hits`, `--subtype`), `parse failures` and `parse summary`, which read an estimate or report zip on this computer, through limits on entries, sizes and compression ratio counted on bytes read (`HostileZip`), and a per-record CSV budget (`limits.csv_max_record_bytes`, `RecordTooLarge`).
- Add `purview case create --topic TEXT` (`--name`, `--requester`, `--description`, `--reuse-existing`). The name comes from `naming.case_name` and the description from `naming.case_description`, which always holds `naming.marker`. Every case is listed first, and a name that any case has, in any status, is refused with `CaseNameInUse`, listing ids and statuses; `--reuse-existing` shows a single active case with the name and sends nothing.
- Add `purview search create <case> --name NAME [query flags]` (`--description`, `--allow-generic --reason TEXT`). The query goes through the guard before sign-in, the case must be active (`CaseNotActive`), and a name in use in the case is refused with `SearchNameInUse`. The body's data source scope is always every tenant mailbox. An echoed query or scope that differs from the one sent is a warning.
- After an unclear outcome, `case create` and `search create` list the cases or searches with the planned name as candidates, by id, and fail with `WriteOutcomeUnknown`.
- Add the safety framework the write commands will run through: a plan with the body serialised once and its SHA-256 digest, approval by `--yes` or an `Apply? [y/N]` prompt at a terminal, `--dry-run` (which wins over `--yes`), exit 3 with `ConfirmationRequired` or `Declined` when nothing is approved, `--no-write` (`PURVIEW_NO_WRITE`) refusing every write before sign-in, and one POST per approved plan that is never sent again; an unclear outcome lists what it may have created and fails with `WriteOutcomeUnknown`.
- `auth login` records in the stored credential whether it was a read-only sign-in. Writes go by that record, because a `--read-only` token still carries `eDiscovery.ReadWrite.All`; a credential stored by v0.1 reads as before, but must sign in again before it can write.
- Check the `naming` templates in `config.json` before a write signs in; an unknown variable is refused without being repeated.
- Errors about `--account`, `--client-id` and `--tenant-id`, and their `PURVIEW_ACCOUNT`, `PURVIEW_CLIENT_ID` and `PURVIEW_TENANT_ID` variables, no longer repeat the value given; they name the flag or variable instead.

## v0.1.0 - 2026-11-27

- Add `purview auth login --browser` using the authorisation code flow with Proof Key for Code Exchange (PKCE) on a loopback redirect (`http://localhost:<port>/callback`), opening the system browser with none of the command's output streams attached.
- Add `contrib/create-purview-app.sh` to create or update the tenant app registration, service principals, assignments and consent grants: dry run by default, `--apply` to make changes, each change sent once and read back on an unclear outcome, and reporting of existing consent grants broader than the plan.
- Add `docs/auth.md` covering permissions, app registration by script or by hand, consent choices, sign-in flows and token storage.
- Add the Microsoft Graph transport: requests only to the exact origin `https://graph.microsoft.com:443` and below `/v1.0/`, paging links checked the same way, redirects disabled, at most three attempts per read with `Retry-After` honoured up to 60 seconds, and one token refresh after a 401.
- Add `purview auth status`, which checks the Graph token and the Purview role with one read and reports `purviewRole` as `ok`, `denied` (HTTP 403) or `unknown`; a refresh the identity platform refuses is an error (exit 1).
- Add the global options `--verbose` (Graph requests and the token refreshes made for them or by `auth refresh`, on stderr through the redactor), `--timeout` (per-request Graph timeout, 0 to 600 seconds) and `--trace DIR` (one JSON file per Graph or download exchange, never a downloaded file's body, with no request headers, only allow-listed response headers and every URL's query values redacted except the OData options and `downloadType`).
- Add `purview case list` (filters `--status`, `--name`, `--created-before`, `--created-after` and `--mine`) and `purview case get`. A `<case>` argument is a case id or an exact display name; several matches fail with `AmbiguousCase`, listing each match's id, status and creation date.
- Add `purview search list` and `purview search get`; `search get` also reads the search's custodian, non-custodial and additional sources.
- Add `purview operation list`, which marks entries the list cannot tell apart as `exportResult?` and refuses `--action report` and `--action export` without `--resolve` (`ResolveRequired`), and `purview operation get`, with `--wait`, `--wait-timeout` and `--poll-interval`. A finished operation that did not succeed exits 4 with an `outcome`; the wait deadline exits 5 (`WaitTimeout`) and Ctrl-C exits 130 (`Interrupted`), each with the command that resumes the wait.
- Redact URL query values (all but the OData options and `downloadType`) in the read commands' output. An error that refuses a `--select` or `<op>` value, or finds no case or search by a name, does not repeat the value; errors about `--account`, `--client-id` and `--tenant-id` can repeat the sanitised value. An error from Graph keeps Graph's message, sanitised and redacted, which can name a case or search.
- Add the global option `--wrap-untrusted` (`PURVIEW_WRAP_UNTRUSTED`), which wraps names, descriptions, external ids, queries and file names in JSON output in `[UNTRUSTED:<id>]` markers and adds an `untrustedNotice`.
- Add `purview download <case> <op>` (`--out`, `--file`, `--overwrite`): it reads the operation again, sends the download token only to the Purview download host each file names, follows only same-origin redirects, streams each file to a temporary file, checks its size and zip central directory, publishes it without replacing a file another writer created (unless `--overwrite` is given), and records its SHA-256 in `manifest.json`. Without `--overwrite`, unchanged recorded files are not fetched again, and existing files with no manifest entry are recorded if they pass verification; a file that cannot be downloaded exits 4 with `FileNotDownloadable` after the others are written, and Ctrl-C exits 130 with the files already written. One command at a time writes into a directory, under `.purview-download.lock`.
- The resume commands after exit 5 and 130 now include `purview download <case> <op>`.
- Add `purview kql [query flags]`, which builds a Keyword Query Language (KQL) query from `--term`, `--participant`, `--since`, `--until`, `--kind` and `--exclude-from`, or takes one with `--kql`, and checks it locally against the guard against generic tenant-wide searches: every branch that can match a message must hold a specific term or a `participants:` restriction on a full address. It prints each term and restriction with its class and the rule that decided it, and exits 1 with `GenericQuery` or `KqlNotUnderstood` otherwise. `guard.specific_terms` and `guard.generic_terms` in `config.json` correct the classifier. `docs/safety.md` documents the grammar, the rules and the built-in generic word list.
- Ship `CHANGELOG.md` and `contrib/create-purview-app.sh` in the release archives, smoke-test `purview kql` in every archive, and run the smoke test again on the signed Apple silicon binary.
- Extend `docs/troubleshooting.md` with keychain prompts after an upgrade, a device code blocked by Conditional Access, 403 without the Purview role, 401 or 403 on a download, `CrossOriginRedirect`, operations that succeeded with failed locations, and cases in `closing` status.
- Add a test that fails if `PATCH`, `PUT` or `DELETE` appears anywhere in the crate's source.
- On macOS and Linux, create lock folders with mode 0700 and lock files with mode 0600, and refuse a linked lock folder; `v0.1.0-rc.1` created them with the default modes.

## v0.1.0-rc.1 - 2026-11-26

- Add the crate skeleton with `purview version`, global output flags (`--json`, `--results-only`, `--plain`, `--select`, `--account`, `--no-input`), terminal sanitisation, redaction across output sinks and the public-data lint (`tests/fixture_lint.rs`).
- Add credentials and device-code sign-in (`purview auth login`, `auth refresh`, `auth list`, `auth logout` and `--read-only`), storing tokens only in the operating system's credential store, redeeming one refresh token for both Microsoft Graph and the Purview download resource, and warning rather than failing at sign-in when the download permission has no consent.
- Serialise sign-in, sign-out and refresh commits for an account across processes with a per-account lock file.
- Add the release pipeline for macOS (Apple silicon and Intel, Developer ID signed and notarised), Linux (x86-64 and Arm64, statically linked) and Windows (x86-64), publishing a build provenance attestation and a checksum for every archive. The Homebrew formula, `aberoham/tap/purview`, lives in a separate tap repository that reads each release.
